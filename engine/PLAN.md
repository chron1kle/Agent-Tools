# Agent Tools Workflow Engine - 计划文档

> **创建日期**: 2026-05-05
> **版本**: 1.0

---

## 一、背景与目标

### 1.1 当前架构问题

现有架构存在以下问题：
- 工具之间相互独立，缺乏统一的编排能力
- 多步骤任务需要外部调度
- 错误处理分散，缺乏统一机制
- 生命周期管理仅支持单工具级别

### 1.2 目标

设计一个**工作流引擎**作为底层基础设施，实现：
- 工具的标准化注册与发现
- 多步骤任务的自动编排
- 统一的错误处理与重试机制
- 完整的生命周期管理
- 可视化监控与日志追踪

## 二、核心概念设计

### 2.1 工作流定义

```
工作流 (Workflow)
├── 元数据 (name, version, description)
├── 步骤 (Steps)
│   ├── Step 1: 工具A
│   ├── Step 2: 工具B (依赖 Step 1)
│   └── Step 3: 工具C (依赖 Step 1+2)
├── 输入 (Inputs)
├── 输出 (Outputs)
└── 配置 (Config)
```

### 2.2 步骤 (Step) 定义

每个步骤包含：
- **工具引用**: 使用哪个工具
- **输入映射**: 如何将上一步输出映射为输入
- **输出映射**: 如何将输出暴露给下一步
- **条件判断**: 何时执行/跳过
- **错误处理**: 失败时的策略

### 2.3 交付物 (Deliverable)

每个步骤/工作流产生：
- 文件 (PDF, EPUB, JSON...)
- 数据 (结构化结果)
- 状态 (成功/失败/部分成功)

## 三、架构设计

### 3.1 分层架构

```
┌─────────────────────────────────────────────┐
│           Workflow Engine                   │
│  ┌─────────────────────────────────────┐  │
│  │  Workflow Executor                   │  │
│  │  - 步骤编排                         │  │
│  │  - 依赖解析                         │  │
│  │  - 并发控制                         │  │
│  └─────────────────────────────────────┘  │
│  ┌─────────────────────────────────────┐  │
│  │  Step Executor                      │  │
│  │  - 工具调用                         │  │
│  │  - 输入/输出映射                    │  │
│  │  - 错误处理                         │  │
│  └─────────────────────────────────────┘  │
│  ┌─────────────────────────────────────┐  │
│  │  Lifecycle Manager                  │  │
│  │  - 启动/停止/监控                   │  │
│  │  - 状态追踪                         │  │
│  └─────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────────┐
│           Tool Registry                     │
│  - 工具注册                               │
│  - 工具发现                               │
│  - 版本管理                                │
└─────────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────────┐
│           Tools (已注册的工具)               │
│  - pdf2epub                               │
│  - 其他工具...                             │
└─────────────────────────────────────────────┘
```

### 3.2 核心模块

| 模块 | 职责 |
|------|------|
| WorkflowExecutor | 工作流编排与执行 |
| StepExecutor | 单步骤执行与错误处理 |
| LifecycleManager | 生命周期管理 |
| ToolRegistry | 工具注册与发现 |
| StateStore | 状态存储与恢复 |
| EventBus | 事件总线（进度、错误） |

## 四、关键设计决策

### 4.1 执行模型

- **DAG 拓扑排序**: 步骤之间允许并行
- **状态机**: 每个步骤有独立状态机
- **事件驱动**: 步骤完成触发下一步

### 4.2 错误处理策略

| 策略 | 行为 |
|------|------|
| RETRY | 重试 N 次 |
| SKIP | 跳过当前步骤 |
| FALLBACK | 使用备用方案 |
| ABORT | 终止整个工作流 |
| COMPENSATE | 执行补偿操作 |

### 4.3 持久化

- 工作流定义: JSON/YAML 文件
- 执行状态: SQLite/内存
- 中间结果: 临时文件
